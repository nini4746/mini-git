# Plan 05: Myers diff 맛보기 (선택)

## 목표

SPEC의 R10 (선택 요구사항)을 구현한다. Myers O(ND) 알고리즘으로 두 파일의 라인 단위 최단 편집 스크립트를 구하는 `minigit diff <fileA> <fileB>`를 만든다. 이 plan은 선택이며, 미구현이어도 프로젝트 완료로 인정된다 (SPEC 완료 판정 참조).

## 컨텍스트

- 선행: 없음 (plan 01~04와 독립. 오브젝트 저장소를 쓰지 않고 파일 대 파일로 동작). 다른 plan과 병렬 가능
- 원전: Eugene Myers, "An O(ND) Difference Algorithm and Its Variations" (1986). 기본형 (greedy, D를 0부터 늘리며 각 대각선 k의 최장 도달점 V[k]를 갱신)만 구현하면 됨. linear space refinement는 범위 밖
- 출력은 최소한으로: 삭제 라인은 `-<라인>`, 추가 라인은 `+<라인>`, 공통 라인은 ` <라인>` 또는 생략. unified diff 헤더 (`@@`)와 hunk 병합은 불요 (SPEC 목표 상태)
- 학습 팁: edit graph를 종이에 그려보고, V 배열 트레이스를 역추적해서 실제 편집 스크립트를 복원하는 부분이 이 알고리즘의 진짜 난관이다. 역추적을 위해 각 D 단계의 V 배열 스냅샷을 보관하는 방식이 기본형에서 가장 단순

## 작업

1. `src/diff.c`: 파일을 라인 배열로 분할 (마지막 개행 없는 라인 처리 주의) → Myers 전진 단계로 D와 트레이스 계산 → 역추적으로 편집 스크립트 복원 → 출력
2. `minigit diff <fileA> <fileB>` 서브커맨드 연결
3. `tests/05-diff.sh` 픽스처:
   - 동일한 두 파일 → 출력 없음
   - 한 줄 삭제 + 한 줄 추가 픽스처 → 편집 수 2
   - 한쪽이 빈 파일 → 전체 추가 / 전체 삭제
   - 편집 수 검증은 `git diff --no-index --numstat` 결과 (추가 + 삭제 수)와 비교

## must-haves

- 편집 스크립트가 최단 (D 최소)임이 픽스처로 확인됨. 단순 LCS DP가 아니라 Myers 전진 탐색으로 구현 (학습 목적이 알고리즘 자체이므로)
- 빈 파일 양쪽 케이스에서 크래시 없음

## 검증

pass/fail 체크리스트 (SPEC R10에서 이 plan 몫):

- [ ] 동일한 두 파일에 대해 출력이 비어 있다
- [ ] 한 줄 삭제 + 한 줄 추가 픽스처에서 편집 스크립트 라인 수가 `git diff --no-index` 기준 최소 편집 수와 일치한다
- [ ] 한쪽이 빈 파일이면 전체 추가 또는 전체 삭제로 출력된다

테스트 명령: `bash tests/05-diff.sh`
